# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AgentCheck audits a website's readiness for AI agents: a CLI (`npx agentcheck-dev <url>`) and a hosted web service on the same engine. Product spec, scoring weights and CLI contract: @docs/spec.md

- Not launched yet (test mode): `https://agentcheck.dev` runs but has no real users, so changes need no redirects for old URLs, no deprecation shims and no compatibility for old data or routes. Migrations must still apply cleanly to the live database (a failing `migrate` stops the deploy). The CLI's `AuditResult` JSON contract counts as public. Remove this bullet at launch.
- Web UI rules (brand, tokens, the plum band, components, icons, account-gated actions, copy): **read `docs/web-ui.md` before changing anything under `apps/web/src`.**
- Docs index: `docs/README.md` (spec, UI rules, deploy).

## Stack and tooling

- TypeScript, ESM only (`"type": "module"`), Node >= 22.18. The CLI is published to npm with a `bin` entry, bundled to `apps/cli/dist/` with tsdown.
- Layout: pnpm workspace — `packages/core` (`@agentcheck/core`, the audit engine), `packages/db` (`@agentcheck/db`, Drizzle schema, migrations, pg-boss queue), `apps/cli` (the CLI, `agentcheck-dev` on npm, command `agentcheck`), `apps/web` (Next.js app, Clerk), `apps/worker` (`@agentcheck/worker`, pg-boss consumer that runs audits).
- Package manager: **pnpm** — never use npm/yarn to install, and don't commit other lockfiles.
- Tests: Vitest. Lint + format: Biome (`pnpm check`, tabs + double quotes). No ESLint/Prettier.
- Run from the repo root: `pnpm check`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm capture`. Before reporting work done: `pnpm check && pnpm typecheck && pnpm test && pnpm build`.
- Run a single test file: `pnpm --filter @agentcheck/core exec vitest run test/x.test.ts` (or `pnpm --filter agentcheck-dev exec vitest run …` for the CLI); by name: add `-t "name"`.
- A PostToolUse hook (`.claude/hooks/biome-format.mjs`) auto-formats every edited file with Biome — expect files to change after Write/Edit (it also turns a never-reassigned `let` into `const`).
- Line endings are LF (enforced by `.gitattributes`).

## Local stack

- `docker compose -f docker-compose.dev.yml up -d` (Postgres on 127.0.0.1:5432), `pnpm --filter @agentcheck/db db:migrate`, then `pnpm --filter @agentcheck/web dev` and `pnpm --filter @agentcheck/worker dev` in two terminals. The worker runs TypeScript directly under Node (no build), logs `worker.scheduled` on boot, reads `DATABASE_URL` from `apps/worker/.env.development` and `AUDIT_CONCURRENCY` from the environment (default 2).
- Stop `next dev` before the commit gate (`pnpm build` collides with it); after `next build`, delete `apps/web/.next` before `next dev` again, or HMR reloads every page in a loop.
- If `next dev` slows to seconds per request or serves stale CSS (new tokens or classes missing in the browser), restart it with a clean `apps/web/.next`.
- Only one `worker dev` may run: a second one (or a `node --watch` parent whose child died) leaves queued audits unclaimed. After a session that started servers in the background, check for stray `--watch src/main.ts` processes.

## Engine rules

- Static checks (manifests, robots.txt, meta tags, markdown twins, semantics) use `undici`/`fetch` + `cheerio` and must work without a browser. Only `packages/core/src/browser/` imports `playwright-core`, lazily via `import()`; the browser is optional (installed Chrome or `npx playwright install chromium`) and never downloaded by AgentCheck.
- Category weights (30/20/25/25) and grade thresholds live in one module; checks return raw results, scoring is computed centrally, never inside a check.
- Every check result must be renderable by all three reporters: terminal, JSON, single-file HTML. The JSON shape (`AuditResult`) is a public CI contract — treat changes to it as breaking; check ids are part of it (stored results, `fixKindsFor` and the reference-site tests key on them), so never rename one. Service-only data (screenshot, favicon) leaves `runAudit` through opt-in callbacks, never through the result. `AuditResult.protocols` (`src/protocols.ts`: agent protocols the site publishes, `{ checked, found }`) is informational and never scored; it is optional because stored results predate it, and every reporter and the web report must render a result without it. `AuditResult.crawl` (`src/crawl.ts`, only with the `crawl` option / `--crawl`) is optional the same way: site checks are marked `scope: "site"` and run once; a new check that answers the same for every page of a site gets that mark.
- A text resource (llms.txt, llms-full.txt, a markdown twin) counts only with status 200, a Content-Type other than `text/html`/`application/xhtml+xml` and a non-empty body that does not start with `<!doctype`/`<html` (`isTextResource`): HTML is rejected rather than text types allow-listed. Site-level files resolve against the origin of the final URL after redirects; an unfetchable target page throws `TargetUnreachableError` (no score).
- The renderer's viewport is fixed at 1280×800, `en-US`, equal to `SCREENSHOT_LARGE` (the small shot is 416×260); changing it shifts the Actionability results and the stored screenshot sizes. Navigation waits for `domcontentloaded`, then at most `LOAD_WAIT_MS` (10 s) for `load` (a stuck tracker never fires it), then network idle.
- `renderHtml` (`packages/core/src/reporters/html.ts`) is one self-contained file: inline CSS, no scripts, no external URLs besides the target and the homepage; it backs the CLI's `--format=html`, and `--format=json` prints the result JSON only (stdout stays clean). `--threshold` failures exit non-zero.
- `packages/core` uses `.ts` relative import specifiers and is consumed as TypeScript source (Node type stripping, Next `transpilePackages`). It is Node-runtime only; `apps/web` keeps `playwright-core` external (`serverExternalPackages`).
- Code that runs as TypeScript under plain node (`packages/*`, `apps/worker`, `apps/cli`) must use erasable syntax only: no parameter properties, enums or namespaces. Vitest and tsc do not catch it.

## Service rules (security and data)

- The network guard (SSRF protection) is opt-in; service code must spread `guardedAuditOptions({ ... })` into the `runAudit` options (it sets `network: { blockPrivate: true }` and a guarded or disabled renderer; `runAudit` refuses any other renderer, and `blockPrivate` refuses a custom `dispatcher`). The CLI stays unguarded and never sets `onScreenshot`/`onFavicon`/`onCheck`.
- The guarded browser proxy connects to the IP it vetted (no second DNS lookup), and Chromium goes through it with `proxy.bypass: "<-loopback>"`, `--disable-quic` and `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`; dropping any of these lets a page reach the network around the guard. The guarded renderer always runs Chromium with its sandbox (`GuardedBrowserRendererOptions` has no `sandbox`); the CLI keeps Playwright's default.
- The worker (`apps/worker/src/process-audit.ts`) builds `runAudit` options **only** with `guardedAuditOptions({ userAgent, toolVersion, browser, onScreenshot, onFavicon, onCheck })`; job payload and anything user-supplied are never spread into audit options, and the worker never passes `dispatcher`, `rendererOptions.resolve`, `isBlocked`, `allowPorts` or its own `network` object. `apps/worker/test/process-audit.test.ts` pins this, including the output keys of `guardedAuditOptions`.
- Untrusted bytes from target sites: the favicon is fetched only by the engine's guarded fetcher (5 s cap, aborted at the cap, ≤100 KB, format by magic bytes); every response `faviconResponse` builds carries the CSP `default-src 'none'; style-src 'unsafe-inline'; sandbox` and `nosniff`. There is no site-wide CSP (`next.config.ts` sets only `Vary: Accept` on `/`, which answers `Accept: text/markdown` with `public/index.md`, and `Link: rel="canonical"` on `/index.md`); if one is added, the favicon's must stay.
- Queue: pg-boss on the same PostgreSQL database (queue `audit`, payload `{ auditId }`, quick jobs priority 10, full 0; `retryLimit: 1`, handler timeout 90 s → `Audit timed out`). The web app enqueues inside the same transaction as the `audits` insert (`createAudit` + `enqueueAudit`); audit outcomes are recorded as `failed`, only infrastructure errors throw (and retry). Status transitions are conditional updates and never overwrite `done`/`failed`; `completeAudit` writes the screenshot and favicon rows in the same transaction, only when the update won.
- Claims are bound to the pg-boss job: `claimAudit`/`claimFixFiles` take `{ jobId }` (the worker passes `job.id`, kept across retries) and store it in `claimed_by`; a `running` row is reclaimed only by that job id (or by any job when `claimed_by` is NULL), another job gets `taken` and is skipped without requeue. Finished checks and an early favicon are written (`recordAuditCheck`, `saveAuditFavicon`) only while the row is `running` and claimed by that job; claim, `completeAudit`, `failAudit` and the sweep clear them.
- `createDb` and `startQueue` default to a 5 s connect timeout (`DEFAULT_CONNECTION_TIMEOUT_MS`), so web requests and the worker fail instead of hanging while Postgres is unreachable.
- The worker owns all pg-boss schedules (`scheduleMaintenance`): queue `maintenance` with `sweep` every 5 min (fails `running` audits and fix-files rows older than 5 min with `Audit timed out`/`Fix files timed out`, and orphaned `queued` ones with `Audit could not be scheduled`/`Fix files could not be scheduled`: `queued_at` older than 15 min **and** no live pg-boss job (`hasLiveJob`: a `created`/`retry`/`active` job in `pgboss.job` on the row's queue with that `auditId`), so a backlog or a stopped worker never fails waiting rows; busy claims refresh `queued_at`) and `retention` daily at 03:00 UTC (deletes anonymous audits older than 30 days; screenshots and favicons go with them by cascade), plus the dead-letter queue `audit_dead`.
- The per-host running cap (`hostRunningMax`) is enforced in `claimAudit` (worker side, requeue after 5 s as a new job; the row stays `queued`). Rate limits are enforced by `enforceLimits` inside `createAudit`'s transaction and nowhere else (`RateLimitError` → HTTP 429 with `Retry-After`); limits live in the single-row `settings` table (`getSettings` is a pure read and returns `DEFAULT_LIMITS` until `updateSettings` stores a row). `enforceLimits` takes transaction advisory locks in a fixed order, `host:<host>` then `user:<id>`/`ip:<hash>`, and `claimAudit`/`claimFixFiles` lock the same `host:` key: keep that order in new locking code. Admins are exempt from per-user daily limits, not from per-host ones; a full audit needs a signed-in user (401) and a blocked user gets 403.
- `audits.host` (host limits, the running cap, history grouping) is the submitted hostname lowercased, without a trailing dot or a leading `www.`.
- The client IP comes only from the last `X-Forwarded-For` entry (IPv6 by /64, sentinel `unknown`) and is stored only as an HMAC with `IP_HASH_SECRET` (required in production).
- Production configuration is validated at server start (`requireProductionEnv` in `apps/web/src/server/env.ts`, called from `apps/web/src/instrumentation.ts`): `ADMIN_EMAIL`, `DATABASE_URL`, `IP_HASH_SECRET` (≥ 32 characters), `PUBLIC_BASE_URL` (an https origin), the Clerk keys and webhook secret; every problem is listed at once, values never echoed. `apps/web/.env.example` lists them.
- Every public link (share link, badge, README report link) comes from `publicOrigin` (`server/share.ts`), which in production is only `PUBLIC_BASE_URL`, never the request's Host or X-Forwarded-Host.
- Submitted URLs are validated with `checkUrl` before anything is stored (`apps/web/src/server/target-url.ts`).
- Access: anonymous audits are visible to anyone with the id, owned audits only to the owner or an admin, everything else is a 404 (`requireAuditAccess`). `currentViewer(audit)` reads the database, never Clerk. The admin is only the verified `ADMIN_EMAIL` account: the role is recomputed on every user sync (`admin` only when the primary email is verified and equals the trimmed `ADMIN_EMAIL`, ASCII-only case folding), mirrored to Clerk `publicMetadata.role` best-effort and never read back for authorisation; blocking lives only in the database. Anonymous audits are never attached to an account after sign-in (a guest's press on Full check or Generate fix files is remembered instead and the check runs again from the account once they are in: `docs/web-ui.md`); `/history` lists only audits started while signed in. Share tokens exist only for done owned audits; `setShareToken` never replaces an existing token (a concurrent create gets the stored one back), only clearing is unconditional. `getAuditByShareToken` answers null while the owner is blocked (the token stays, unblocking restores the link), so `/r/[shareToken]`, the badge and the shared export, screenshot and favicon all stop together.
- Protected pages and route handlers in `apps/web` call `await auth.protect()` themselves (`apps/web/src/proxy.ts` is a bare `clerkMiddleware()`). Route files that are public by design are in the `PUBLIC` allowlist of `apps/web/test/app/protection.test.ts` and authorise inside; the test requires `await auth.protect(` or one of `requireAdmin(`, `requireActiveUser(`, `requireAuditAccess(`.
- Audit-scoped routes come in pairs that follow the audit's own access rules: by id (`/api/audits/[id]/{export,screenshot,favicon}`, guarded by `requireAuditAccess(`, not allowlisted) and by share token (`/api/shared/[token]/{export,screenshot,favicon,badge.svg,og.png}` and `/r/[shareToken]`, allowlisted, authorised via the token lookup). The badge and `og.png` exist only for shared audits (`og.png`: lookup first, then a small LRU of rendered PNGs keyed by audit id). Caching: share-token images (`og.png` too) `public, max-age=300` (an unshared link stops serving within minutes), by-id images `private, max-age=3600`, 404s `no-store`, the badge `public, max-age=86400`; export answers 404 (not 409) for an unfinished audit.
- Clerk webhook `/api/webhooks/clerk` is authorised only by its signature (`verifyWebhook`, `CLERK_WEBHOOK_SIGNING_SECRET`), never `auth.protect()`; `user.deleted` calls `deleteUserData` (the user and all their audits, one transaction, idempotent); a database error throws so Clerk retries.
- Legal: `/privacy` and `/terms` are static public pages on `LegalPage`; their markdown versions `public/privacy.md` and `public/terms.md` follow them through a file snapshot (`vitest -u` in `apps/web` after editing the text); operator, contact, date and licence live in `apps/web/src/content/legal.ts`. They describe only the hosted service; when data handling changes (new fields, processors, retention), update the text and the "updated" date. A test pins the stated anonymous retention to `ANONYMOUS_RETENTION_DAYS`.
- Fix files: `@agentcheck/core/fixes` (`generateFixFiles`, `fixKindsFor`, `FIX_KIND_ORDER`) builds `robots.txt`, `llms.txt`, `llms-full.txt`, the audited page's markdown twin (`pricing.md`; stems `readme`, `agent-prompt` and Windows device names become `<stem>-page.md`) and `head.html` from the site's own pages (static, no LLM, no browser; HTML to markdown in `fixes/markdown.ts`; head.html and the twin from the audited page, llms.txt and the menu from the site root). Everything it reads goes through `createFetcher`; the generator never leaves the site's host and skips a file with a reason when its input is unreadable (an unreadable robots.txt is never replaced). Untrusted site text is cleaned in `fixes/text.ts`. The robots rule: an AI crawler gets the `*` rules minus whatever blocks the audited URL. The README and agent prompt are pure functions in `fixes/pack.ts` (shared by web and CLI). `AuditResult` is not changed.
- The worker (`apps/worker/src/process-fix-files.ts`) calls `generateFixFiles` **only** with `guardedFixOptions({ userAgent, toolVersion })` plus `signal`/`onProgress`; the payload and the row never reach the options (only the URL and the kinds are inputs). `apps/worker/test/process-fix-files.test.ts` pins the option keys. Outcomes are recorded as `failed`, only infrastructure errors throw.
- Fix files table `audit_fix_files` (one row per audit, cascade with it): `createFixFiles` + `enqueueFixFiles` in one transaction; a `done` row is never regenerated, a `failed` one may restart, at most 3 attempts per audit (`FIX_FILES_MAX_ATTEMPTS`, 409 after); no rate-limit setting, `enforceLimits` stays the only limiter. Queue `fix_files` (payload `{ auditId }`, `retryLimit: 1`) dead-letters into `fix_files_dead`, which fails the row; `sweep` also fails fix rows `running` longer than 5 min with `Fix files timed out`; the worker runs `AUDIT_CONCURRENCY` fix jobs at once, but only one per host at a time (`claimFixFiles`), each with a 60 s handler timeout (`FIX_FILES_TIMEOUT_MS`). `fixKindsFor` asks for robots only when `ai-bots-allowed` has details (none means robots.txt was unreadable) or `content-signals` is `fail` (no signal: the generator adds `DEFAULT_CONTENT_SIGNAL`, `search=yes, ai-input=yes, ai-train=no`, and never changes an existing one), and for a twin only when `markdown-twin` is `fail`.
- Fix-files routes (`/api/audits/[id]/fix-files` and `/api/audits/[id]/fix-files/[name]`, where `[name]` is a file name or the reserved `zip` or `prompt`) use `requireAuditAccess(`; generating is owner only (403), reading is owner or admin, anonymous audits never have fix files, and there are no `/api/shared/...` variants or files on `/r/[shareToken]`. Downloads are `attachment` + `nosniff` + `private, no-store`; file text is rendered as React text, never `innerHTML`. A file is downloadable only if its name is stored for that audit and matches `FILE_NAME` (`/^[a-z0-9][a-z0-9._-]*\.(txt|md|html)$/`); `.md` is served as `text/markdown; charset=utf-8`, the others as `text/plain; charset=utf-8`. The zip is a pure function in `apps/web/src/server/fix-files-pack.ts`. The download name `prompt` serves `agentPrompt` (the zip's `AGENT-PROMPT.md`) as `text/plain`, file name `AGENT-PROMPT.txt`, with the same headers, only when at least one file was built. `fixFilesView` (the page and the polled JSON) never carries whole files or the prompt: each file's `content` is cut to `FIX_PREVIEW_MAX` (20 KB, `components/report/fix-files/preview.ts`) at a line boundary with `previewOf` = the full length, and `hasPrompt` replaces the prompt; the zip and the downloads read the stored row.
- CLI `agentcheck fix <url>` (`apps/cli/src/fix.ts`) writes the fix files plus `README.md` and `AGENT-PROMPT.md` into a directory (`--out`, default `./agentcheck-fix`). It runs unguarded like the rest of the CLI, never overwrites without `--force` (checks first, then exclusive `wx` writes), refuses file names outside `SAFE_NAME`, and with `--only=KINDS` skips the audit.
- `@agentcheck/db` main entry never imports PGlite; test helpers live in `@agentcheck/db/testing`.

## Testing

- Tests never hit the real network. Mock HTTP with undici `MockAgent`; keep HTML/robots/llms.txt samples as fixtures under `packages/core/test/fixtures/`.
- Expected outcomes for the reference sites (`good`, `mixed`, `poor`) live in `packages/core/test/e2e/reference-sites.test.ts`; the sites under `packages/core/test/fixtures/sites/<name>/` are synthetic, hand-made fixtures (fictional content on `https://<name>.example`, no live captures). Change a page there by hand when a check needs a new case.
- Playwright tests run against local fixture pages served from a local server, not live sites.
- Database and queue tests run on PGlite via `@agentcheck/db/testing` (`createTestDb()`, `startTestQueue()`); pg-boss runs in-process there, so no Docker is needed. A PGlite boot costs about a second, so `close()` wipes the database (`resetTestDb`: every table truncated, pg-boss's schema dropped) and the next `createTestDb()` in the same test file reuses the instance; stop every queue before `close()`. Worker tests fake `runAudit`.
- Web tests live in `apps/web/test/` (mirroring `src/`) and import sources through the `@/*` alias, never relative paths into `src/`; they stay in the node environment with `renderToStaticMarkup`; interaction tests opt into jsdom per file with `// @vitest-environment jsdom` and Testing Library.

## Deploy

- How to release, deploy, roll back and change secrets: `docs/deploy.md`. Stack files live in `deploy/` (`deploy/edge/` is the server's shared Caddy; AgentCheck publishes no ports and joins the `edge` network as `agentcheck-web`).
- Release = a tag `vX.Y.Z` (`gh release create vX.Y.Z --generate-notes`). The five released packages (`scripts/release-packages.mjs`) keep the placeholder version `0.0.0-dev` in the repository; the release workflow runs `node scripts/set-version.mjs X.Y.Z` from the tag before it builds, so the images, the CLI and every report carry the real version. The workflow then builds the images, publishes the CLI to npm (trusted publishing, no token, only with the repository variable `NPM_PUBLISH=true`) and deploys through `deploy.yml` once the `production` environment's reviewer approves; the server runs the tag named in `AGENTCHECK_VERSION`, never `latest`.
- Secrets never enter the repository, images or chat: Clerk keys go GitHub secrets → "Sync server secrets" → `.env`; `ADMIN_EMAIL`, `POSTGRES_PASSWORD`, `IP_HASH_SECRET` exist only in the server's `.env`. The CI deploy key's forced command is `deploy/bin/ci`, which runs only `set-env` (the Clerk keys) or `deploy vX.Y.Z` (`deploy/bin/deploy`: installs the stack files sent on stdin from a whitelist, sets the tag, pulls, restarts, checks the services); `deploy/test/deploy.test.ts` pins both.
- Production Chromium runs with its sandbox (guarded renderer sets `sandbox: true`; the worker container uses `deploy/seccomp-chromium.json`). Never fall back to `--no-sandbox`.

## Git

- Nothing is committed to `main` directly, not even by the maintainer: every change goes through a pull request from a branch (`feat/...`, `fix/...`), merged once the CI gate (`.github/workflows/ci.yml`) is green; the branch ruleset on GitHub enforces it. Conventional Commits (`feat:`, `fix:`, `chore:`, `test:`, `docs:`, `refactor:`).
